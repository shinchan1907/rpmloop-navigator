# Contributing

Thanks for helping develop RPMLOOP Navigator.

For a hardware issue, include the design revision, exact component variant,
print material/process, measured dimensions, photos and a reproducible test.
Clearly distinguish observations from assumptions.

For a proposed CAD change, provide the editable source, regenerated parts,
clearance/mesh checks and relevant views. Keep PCB, active display, touch,
window and gasket definitions independent. Never replace an unverified
dimension silently or claim environmental performance from a render.

Firmware and companion-app implementations are still to come. Open an issue
to discuss protocol or architecture changes before a large implementation.
Keep credentials, private navigation/location data and personal files out of
commits. Small, focused pull requests are easiest to review.
